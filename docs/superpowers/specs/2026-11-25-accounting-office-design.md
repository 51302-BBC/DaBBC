# 會計事務所內部管理系統設計

本設計依據 [產品背景](../../../PRODUCT.md)、[需求文件](../../requirements.md) 與已確認的架構討論。第一版服務單一臺灣會計事務所，交付已確認功能的可操作 Web 介面，包含報帳及個人資料修改。功能範圍與營運規則以需求文件為準。

## 架構選擇

- **已選定**：共用一套 React 網站、一個按業務模組組織的 FastAPI 後端與一個 PostgreSQL 資料庫。Docker Compose 啟動前端、API 及資料庫。共用帳號、角色、通知與導覽，適應同一人兼任多個角色的工作方式。
- **曾考慮**：將任務與人事出勤拆成兩個獨立應用。可各自部署，但需跨應用整合帳號、組織、權限與通知。第一版採用共用部署。

第一版聚焦內部工作、出勤、審核及報表。獨立應用部署與多事務所支援均在本版範圍之外。

## 後端 MVC 分層

依帳號與組織、客戶與任務、班表與出勤、申請與審核、報表、通知劃分模組。各模組按需要設置下列層級。

| 層級 | 責任 |
| --- | --- |
| Controller | FastAPI Router 解析請求、取得登入身分、呼叫 Service 並回傳結果。 |
| View | React 呈現頁面，API 回應模型定義各用途能取得的欄位。 |
| Model | 表達業務資料與狀態規則，例如申請可撤回的狀態與額度的保留、扣除和返還。 |
| Service | 協調用例、執行 policy 授權、呼叫業務規則和 Repository，管理交易邊界。 |
| Repository | 封裝 PostgreSQL 查詢與寫入，提供所需的資料存取操作。 |

同一帳號取得各角色所授予權限的聯集。後端按每次操作及其資料範圍檢查授權，例如主管核准其負責的假單，兼任行政時另取得補打卡審核權。前端依授權結果顯示導覽和操作。申請審核另外檢查指派關係與禁止自審規則。

核准假單時，審核 Service 完成授權及狀態檢查後，在同一筆資料庫交易更新申請、額度和審核歷程。行事曆讀取核准結果，公開姓名、時段和狀態。申請詳情使用獨立的 API 回應欄位，依權限提供假別、事由與附件。出勤保留原始打卡與補正紀錄，報表保留定稿及後續版本。

當同一流程需要多套有效業務規則時，用 **Strategy** 封裝差異，例如工時計算或審核路由。實作確實需要集中選擇或組裝時，再引入 **Factory**。郵件與憑證儲存透過 **Adapter** 接入，讓 Service 依賴穩定介面，正式供應商與部署設定待確認。

## 頁面與元件

| 功能區 | 主要頁面 | 元件 |
| --- | --- | --- |
| 帳號與工作台 | 登入、啟用帳號、重設密碼、工作台、通知中心 | 共用網站框架、權限導覽、今日打卡、我的任務、待審摘要 |
| 任務與客戶 | 我的任務、任務總覽與詳情、客戶公司清單與詳情 | 任務篩選、分派與改派表單、狀態操作、變更歷程、負責人清單 |
| 出勤與行事曆 | 打卡與個人出勤、假別餘額、公司行事曆、班表設定 | 手機打卡按鈕、逐日紀錄、缺卡標記、請假餘額、假日與調班事件 |
| 申請與審核 | 我的申請、新增申請、申請詳情、審核收件匣、待指派清單 | 各類型表單、憑證上傳、審核歷程、退回原因、撤回與撤銷操作、報帳付款標記 |
| 員工與權限 | 員工清單與詳情、組織與角色設定、代理審核、離職交接 | 直屬主管選擇、角色分配、代理期間、交接清單、假別與時數設定 |
| 報表與月結 | 工時明細、請假與加班彙總、月結定稿與歷史版本 | 日期與員工篩選、逐日工時表、異常標記、Excel 匯出、版本清單 |

請假、外出、加班、補打卡、報帳與個資修改各自有表單與驗證規則，共用申請狀態呈現、審核歷程和操作區。

任務總覽提供老闆查看全所工作狀態。

## 開放決策與實作空間

工時與假勤的正式計算規則、間接下屬的權限、代理資格與順序、任務操作邊界、月結授權與正式報表、部署與資料留存，依需求文件的待確認事項及定案時點處理。可先規劃已確認的流程，對應規則定案後再完成受影響的操作與驗收。

行政審核的分派方式仍待確認。補打卡、報帳及個資修改可採共用待審清單或指派個別審核人，須在實作行政審核路由與通知前定案，並涵蓋申請人兼任行政時的處理方式。

前端路由、API 路徑、資料庫綱要、套件選用、假日匯入方式，以及有無必要引入 Strategy 或 Factory，由實作規劃依需求決定。

## 驗收重點

- Docker Compose 可啟動系統，各已確認功能透過正常操作流程讀寫資料。
- 兼任角色的帳號可使用授權範圍內的功能，直接呼叫 API 也須符合相同授權規則。
- 員工送件、主管或行政審核，以及待指派與撤銷流程，依需求留存歷程。假單審核與額度更新一致。
- 同事可看到行事曆公開資訊。具備明細權限者可另行查看申請資料。
- 行政可依期間和員工匯出報表，查閱出勤補正與定稿後的版本。
